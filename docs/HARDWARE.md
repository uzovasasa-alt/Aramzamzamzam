# Датчики и CAN: где взять и как проверить приложение

Этот документ про этап 2: GPS-трекеры, датчики уровня топлива (ДУТ) и чтение CAN-шины.
Приложение уже умеет принимать их данные, а проверить это можно четырьмя способами, от бесплатного к «боевому».

## Как устроена цепочка

```
 Трактор                      Трекер                       Наш сервер
 ┌───────────────┐   CAN    ┌──────────────┐  GSM/TCP   ┌──────────────────────────┐
 │ ЭБУ двигателя ├─────────►│ GPS-трекер   ├───────────►│ шлюз Teltonika  :5027    │
 │ (J1939)       │ (через   │ + CAN-адаптер│            │ шлюз Wialon IPS :20332   │
 └───────────────┘  CAN-    │ + ДУТ RS-485 │            │ HTTP /api/telemetry/...  │
 ┌───────────────┐  считыв.)└──────────────┘            └────────────┬─────────────┘
 │ ДУТ в баке    ├──RS-485──►                                         ▼
 └───────────────┘                                     телеметрия → поиск сливов → нарушения
```

Важно понимать, что на CAN-шине **нет «датчика уровня топлива» как отдельного устройства**. CAN — это провода, по которым блоки трактора обмениваются сообщениями. Уровень топлива там есть, только если его передаёт штатная электроника машины. В тракторах с электронными двигателями (Кировец К-7М, Ростсельмаш, импортная техника, часть МТЗ с двигателями Stage IIIa и выше) это обычно параметры SAE J1939: Fuel Level (SPN 96), Engine Total Hours (SPN 247), Total Fuel Used (SPN 250). На старых МТЗ и ЮМЗ с механическими двигателями CAN нет вовсе, и там ставят погружной ДУТ в бак.

## Способ 1. Без железа: симулятор (уже в проекте)

Симулятор работает как настоящий трекер: подключается к серверу по тем же протоколам и отправляет те же байты.

```bash
# 1. Добавьте технике в веб-панели IMEI 356307042441013 и шаблон «Teltonika + CAN»
# 2. Отправьте сутки данных со «сливом» 60 л ночью:
npx tsx simulator/sim.ts tracker --protocol teltonika --imei 356307042441013 --scenario drain
# 3. Веб-панель → Техника → Кировец → «Проверить на сливы» → в «Нарушениях» появится слив
```

Есть и другие сценарии: `normal` (ложных срабатываний быть не должно), `refuel` (заправка не внесена в систему), `night-move` (движение без смены). Протоколы: `teltonika`, `wialon`, `http`. Симулятор водителя (`driver`) проверяет мобильный API без телефона: `--scenario overuse | outside | hours-padding`.

## Способ 2. Стенд на столе: виртуальная или настоящая CAN-шина (≈1–3 тыс. ₽)

Этот способ нужен, чтобы команда своими руками увидела J1939-кадры и проверила свой CAN-модуль.

* **Совсем без железа (Linux):** виртуальная шина `vcan`.
  `sudo modprobe vcan && sudo ip link add dev vcan0 type vcan && sudo ip link set up vcan0`,
  затем `cangen vcan0` / `candump vcan0` из пакета `can-utils`, а J1939-кадр уровня топлива можно отправить вручную, например:
  `cansend vcan0 18FEFC00#FF7DFFFFFFFFFFFF` (PGN 65276 «Dash Display», байт 2 = 0x7D = 125 × 0.4 % = 50 %).
* **USB-CAN адаптер:** CANable / CANable 2.0 (открытый проект, есть клоны на AliExpress и Ozon), работает со `slcan`/`candleLight` в Linux, Windows и macOS. Два адаптера, соединённые витой парой с терминаторами по 120 Ом, дают настоящую шину на столе: один «изображает трактор», второй слушает.
* **Своё устройство:** ESP32 + трансивер SN65HVD230 (или Arduino + MCP2515) читает J1939 и шлёт JSON на `POST /api/telemetry/ingest` (протокол `HTTP`, шаблон «Своё устройство»). Получается хороший учебный проект для команды и дешёвая альтернатива трекеру для пилота.

## Способ 3. Настоящий трекер на стенде (≈10–25 тыс. ₽ за комплект)

Минимальный комплект: трекер с CAN, SIM-карта с интернетом и блок питания на 12 В. ДУТ по желанию.

| Что | Варианты | Комментарий |
|---|---|---|
| Трекер с CAN | **Teltonika FMC150** (CAN встроен), FMB140 / FMC130 + адаптер **ALL-CAN300** или **LV-CAN200** | Протокол Codec 8/8E — уже поддержан (порт 5027). У Teltonika подробная wiki и бесплатный конфигуратор |
| Трекер (Россия) | **Арнави**, **Навтелеком Смарт**, **Galileosky** | Арнави и Навтелеком умеют Wialon IPS (порт 20332) — уточните в документации модели. У Galileosky свой протокол и ЕГТС — понадобится ещё один парсер |
| ДУТ в бак | **Omnicomm LLS 5 / LLS Neo**, **Эскорт ТД-150/500**, **Технотон DUT-E** | Подключается к трекеру по RS-485 или аналогом. Нужна **тарировка** — проливка бака по 10–20 л с записью показаний: эту таблицу вводят в поле `calibration` |
| Бесконтактный CAN-считыватель | **Технотон CANUp**, CAN-LOG, **Teltonika ECAN02** | Снимается с проводов шины без врезки — гарантия на технику не теряется |

Где найти:
1. **Дилеры и интеграторы мониторинга в регионе.** В Мордовии, Пензе и Нижнем Новгороде есть установщики ГЛОНАСС-мониторинга. Многие дают оборудование на тест или продают б/у. Достаточно спросить у них «демо-комплект трекер + ДУТ для студенческого проекта».
2. **Производители напрямую.** У Omnicomm, Эскорт, Технотон, Арнави и Galileosky есть программы для вузов, стартапов и партнёров. Письмо от университета (МГУ им. Огарёва) с описанием проекта часто помогает получить образцы бесплатно или со скидкой. Это закрывает пункт «тестовый комплект IoT-датчиков» из вашего запроса.
3. **Маркетплейсы (Ozon, Wildberries, Avito, AliExpress).** Там продаются Teltonika FMB/FMC, клоны CANable, модули MCP2515 и SN65HVD230. Б/у трекеры на Avito стоят заметно дешевле.
4. **Технопарк вуза и акселератор.** Попросите выделить средства на «тестовый комплект датчиков для этапа 2»: это есть в слайде «Запрос».

> Цены и наличие быстро меняются, поэтому суммы выше ориентировочные. Проверьте их у продавцов перед закупкой.

## Способ 4. Пилот на технике партнёра

ООО «Франц Кляйне» и хозяйства из проблемных интервью — лучший полигон. План пилота:
1. На **1–2 машины с электронным двигателем** ставится трекер с бесконтактным CAN-считывателем. Бак не трогаем.
2. На **1 старую машину** (МТЗ-82/1221) ставится ДУТ с тарировкой.
3. **2–4 недели** водители работают в приложении как обычно, а сервер параллельно получает телеметрию.
4. Сверяем отчёты: «расход по водителю» против «расход по датчику», смотрим найденные сливы и ложные срабатывания. Пороги настраиваются в «Настройках хозяйства».

## Что проверить в первую очередь (чек-лист тестировщика)

- [ ] Трекер подключился: в логах backend есть `Teltonika: подключён <IMEI> (<техника>)`
- [ ] На карточке техники статус «на связи», а график уровня топлива строится
- [ ] Сценарий `normal`: **нет** ложных сливов на ходу (плеск топлива, кочки)
- [ ] Сценарий `drain`: слив найден, приходит уведомление в веб-панели (и в Telegram, если настроен)
- [ ] Сценарий `refuel`: «заправка не зарегистрирована», а после внесения заправки в веб-панели нарушение не появляется повторно
- [ ] Ручные показания водителя расходятся с датчиком больше порога → «Показания водителя расходятся с датчиком»
- [ ] Трекер был без связи (чёрный ящик): точки пришли пачкой позже, дублей нет
- [ ] ID параметров (`io89`, `io102`, `fuel_lvl`…) сверены с документацией **вашей** модели трекера: у разных моделей они разные
