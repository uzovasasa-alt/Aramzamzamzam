# АгроКонтроль: контроль топлива и рабочего времени сельхозтехники

MVP проекта команды МГУ им. Огарёва. Он закрывает три проблемы из презентации: **сливы топлива**, **приписки моточасов** и **отсутствие прозрачности** для руководителя.

| Часть | Что делает | Стек |
|---|---|---|
| `android/` | Приложение водителя: старт смены только на базе (геозона), фото моточасов и топлива, заправки, запись трека, **полностью офлайн** | Kotlin, Jetpack Compose, Room, WorkManager, Foreground Location Service |
| `backend/` | API, идемпотентная синхронизация, антифрод-правила, шлюзы трекеров (Teltonika, Wialon IPS, HTTP), уведомления | NestJS, PostgreSQL + PostGIS, фото на диске или в S3 |
| `web/` | Панель диспетчера и администратора: сводка, проверка смен, нарушения, техника и датчики, базы на карте, отчёт в Excel | React, Vite, Leaflet |
| `simulator/` | Имитация трекеров (сливы, заправки, ночные поездки) и водителя — проверка без железа | TypeScript |
| `docs/` | [Где взять CAN-датчики и как тестировать](docs/HARDWARE.md), [контракт API синхронизации](docs/API.md) | |

## Быстрый старт (Docker)

> 📘 **Подробная пошаговая инструкция — [docs/SETUP.md](docs/SETUP.md)**: установка программ, запуск, эмулятор и телефон, симулятор, решение проблем, запуск на сервере.

Нужен Docker Desktop.

```bash
docker compose up -d --build
docker compose exec backend npm run seed:prod   # демо-хозяйство, техника, 2 недели смен
```

* Веб-панель: http://localhost:8080 — логин `admin` / `admin123` (или `moderator` / `moder123`)
* Документация API (Swagger): http://localhost:3000/api/docs
* Водители для приложения: `ivanov` / `1111`, `petrov` / `2222`, `sidorov` / `3333`
* Суперадмин (подключает новые хозяйства): `superadmin` / `superadmin`

В демо-данных уже есть нарушения: перерасход на МТЗ, «приписка» моточасов на комбайне, пропажа топлива между сменами и ночной слив по датчику на Кировце.

## Разработка без Docker

```bash
# База: PostgreSQL 14+ с PostGIS (или только БД из compose: docker compose up -d db)
cd backend && cp .env.example .env && npm install
npm run start:dev          # миграции применяются автоматически
npm run seed               # демо-данные
npm test                   # юнит-тесты правил, парсеров протоколов, детектора сливов

cd ../web && npm install && npm run dev    # http://localhost:5173, /api проксируется на :3000
```

**Android:** откройте папку `android/` в Android Studio (Koala или новее) и запустите на эмуляторе.
По умолчанию приложение ходит на `http://10.0.2.2:3000`, то есть на ваш компьютер из эмулятора. На реальном телефоне в той же Wi-Fi сети укажите на экране входа `http://<IP компьютера>:3000`.
Чтобы «оказаться на базе» в эмуляторе: Extended controls → Location → координаты базы (демо: 54.1063, 44.9395).

## Проверка без телефона и без датчиков

```bash
# «водитель» отправляет смену с перерасходом через мобильный API (и повторяет пакет — проверка, что дублей нет)
npx tsx simulator/sim.ts driver --login ivanov --password 1111 --scenario overuse
# «трекер Teltonika» шлёт сутки данных со сливом 60 л
npx tsx simulator/sim.ts tracker --protocol teltonika --imei 356307042441013 --scenario drain
```

## Как работает антифрод

| Нарушение | Как ловим |
|---|---|
| Старт смены не на базе | Телефон не даёт начать смену вне круга базы, а сервер перепроверяет координаты в PostGIS (`ST_Distance`) |
| Фиктивный GPS | Android сообщает `isMock`, и такая смена помечается |
| Подкрученные часы телефона | «Честное время» = время сервера при последней синхронизации + монотонные часы телефона, а после перезагрузки — время GPS |
| Приписка моточасов | Наработка больше длительности смены; счётчик меньше, чем в конце прошлой смены; техника работала между сменами |
| Слив / перерасход | Расход = остаток на старте + заправки − остаток в конце, сравнивается с нормой л/моточас и допуском. Отдельно проверяется пропажа топлива между сменами |
| Нет доказательств | Обязательные фото показаний. SHA-256 считается на телефоне в момент съёмки, сервер сверяет его при загрузке |
| Слив по датчику | Медианное сглаживание ДУТ и поиск падения ≥ N л за M минут на стоянке. Плеск на ходу сливом не считается |
| Незарегистрированная заправка, движение без смены, расхождение ручных показаний с датчиком | Сверка с телеметрией |

Все пороги настраиваются в веб-панели («Настройки») для каждого хозяйства и для каждой единицы техники (норма и допуск).

## Структура и ключевые файлы

```
backend/src/domain/rules.ts               правила проверки смены (чистые функции, покрыты тестами)
backend/src/domain/telemetry-analysis.ts  тарировка ДУТ, поиск сливов и заправок
backend/src/mobile/sync.service.ts        идемпотентная синхронизация
backend/src/telemetry/parsers/            Teltonika Codec 8/8E, Wialon IPS 1.1/2.0
backend/src/database/migrations/          схема БД (PostGIS)
android/.../data/Repository.kt            действия водителя (только локальная БД)
android/.../sync/SyncWorker.kt            фоновая отправка
android/.../domain/GeoFence.kt            геозона (та же логика, что на сервере)
web/src/pages/Shift.tsx                   экран проверки смены модератором
```
