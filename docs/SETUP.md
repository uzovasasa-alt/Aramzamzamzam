## 1. Что получится в итоге

```
 Ваш компьютер (Docker)                                   Телефон / эмулятор
┌─────────────────────────────────────────────────┐     ┌─────────────────────┐
│ web      веб-панель           localhost:8080    │     │ Приложение водителя │
│ backend  API                  localhost:3000 ◄──┼─────┤ (Android)           │
│          шлюзы трекеров       :5027, :20332     │     └─────────────────────┘
│ db       PostgreSQL + PostGIS localhost:5432    │     ┌─────────────────────┐
│ photos   том Docker с фото показаний         ◄──┼─────┤ Симулятор трекера   │
└─────────────────────────────────────────────────┘     └─────────────────────┘
```

Сервер, базу и веб-панель поднимает одна команда Docker. Фото показаний хранятся в томе Docker `photos`. Мобильное приложение собирается отдельно в Android Studio.

## 2. Что установить

| Программа | Зачем | Где взять | Проверка в терминале |
|---|---|---|---|
| **Git** | скачать код | macOS: появится сам при первом вызове `git` (предложит Command Line Tools). Windows: https://git-scm.com | `git --version` |
| **Docker Desktop** | сервер, база, веб-панель | https://www.docker.com/products/docker-desktop/ — на Mac берите версию для **Apple Silicon** | `docker --version` и `docker compose version` |
| **Node.js 20 LTS** или новее | симулятор, тесты, режим разработки | https://nodejs.org (кнопка LTS) или `brew install node@20` | `node -v` (должно быть v20 или выше) |
| **Android Studio** (Koala 2024.1 или новее) | мобильное приложение | https://developer.android.com/studio | — |

После установки Docker Desktop:
1. Запустите Docker Desktop и дождитесь зелёного статуса **Engine running** внизу слева.
2. **Только Mac на M1/M2/M3:** откройте Settings → General и включите **Use Rosetta for x86_64/amd64 emulation on Apple Silicon**. Образ PostGIS собран только под x86, и через Rosetta он работает быстрее.
3. Settings → Resources: выделите Docker не меньше **4 ГБ памяти** (по умолчанию обычно хватает).

> **Windows:** при установке Docker Desktop согласитесь на WSL 2. Команды из инструкции выполняйте в PowerShell или Git Bash.

## 3. Скачать проект

Откройте **Терминал** (macOS: Spotlight → «Терминал») и выполните:

```bash
cd ~/IdeaProjects            # или любая папка, где вы храните проекты
git clone https://github.com/Kupo2007/aramsamsam.git
cd aramsamsam
ls
```

Должны появиться папки `android`, `backend`, `web`, `simulator`, `docs` и файл `docker-compose.yml`.

> Если репозиторий приватный, git спросит логин и пароль. Вместо пароля нужен **Personal Access Token**: GitHub → Settings → Developer settings → Personal access tokens. Либо клонируйте через GitHub Desktop.

## 4. Запуск сервера и веб-панели в Docker

### 4.1. Сборка и запуск

В папке проекта выполните:

```bash
docker compose up -d --build
```

Первый запуск занимает **5–15 минут**: Docker скачивает образы PostGIS, Node.js и nginx и устанавливает npm-пакеты. Следующие запуски проходят за секунды.

`-d` значит «в фоне», `--build` — пересобрать backend и веб из исходников.

### 4.2. Проверка, что всё поднялось

```bash
docker compose ps
```

Должны быть 3 сервиса со статусом `running` (у `db` дополнительно `healthy`):

```
NAME                   SERVICE   STATUS
aramsamsam-backend-1   backend   Up
aramsamsam-db-1        db        Up (healthy)
aramsamsam-web-1       web       Up
```

Посмотрите логи backend:

```bash
docker compose logs -f backend
```

Нужные строки выглядят так:

```
Teltonika: слушаю TCP 5027
Wialon IPS: слушаю TCP 20332
API: http://localhost:3000/api  ·  Документация: http://localhost:3000/api/docs
```

Выйти из просмотра логов: `Ctrl + C` (сервер при этом продолжит работать).

Проверка из браузера: откройте http://localhost:3000/api/health. Ответ `{"ok":true,...}` значит, что backend работает и видит базу.

### 4.3. Демо-данные

```bash
docker compose exec backend npm run seed:prod
```

Команда создаёт демо-хозяйство «Нива» с двумя базами, четырьмя единицами техники, сотрудниками и двумя неделями смен. Среди смен есть нарушения: перерасход, приписка моточасов, пропажа топлива и ночной слив по датчику.
В конце должна появиться строка `Готово! Логины: …`. Повторный запуск ничего не дублирует.

### 4.4. Учётные записи демо-данных

| Кто | Логин | Пароль | Где входить |
|---|---|---|---|
| Администратор хозяйства | `admin` | `admin123` | веб-панель |
| Модератор (диспетчер) | `moderator` | `moder123` | веб-панель |
| Водитель | `ivanov` | `1111` | мобильное приложение |
| Водитель | `petrov` | `2222` | мобильное приложение |
| Водитель | `sidorov` | `3333` | мобильное приложение |
| Суперадмин платформы | `superadmin` | `superadmin` | веб-панель (подключение новых хозяйств) |

## 5. Первый вход в веб-панель

Откройте http://localhost:8080 и войдите как `admin` / `admin123`.

Что посмотреть по порядку:
1. **Сводка**: общий расход и норма, график по дням, новые нарушения, техника «факт против нормы».
2. **Нарушения**: красная точка означает высокую важность. Кнопка «Открыть смену» ведёт к деталям.
3. **Смены** → смена со статусом «Ждёт проверки»: показания на старте и в конце, карта, расход против нормы. Здесь можно **принять** смену или **отклонить** её с комментарием, который увидит водитель.
4. **Техника → Кировец К-742 №3**: график уровня топлива с датчика и найденный слив.
5. **Базы**: круги геозон на карте. Чтобы добавить свою базу, нажмите «Добавить базу», кликните по карте и выставьте радиус.
6. **Настройки**: пороги проверки (допуск перерасхода, точность GPS и т. д.).

Другие адреса:
- **Swagger** (все методы API, можно вызывать прямо из браузера): http://localhost:3000/api/docs. Нажмите Authorize и вставьте `accessToken` из ответа `/api/auth/login`.
- **Фото** лежат в томе Docker `photos`. Посмотреть файлы: `docker compose exec backend ls -R /data/photos`.

> Фото в демо-сменах не загружены (их создал скрипт), поэтому в карточке смены вместо снимков написано «ждёт». Настоящие фото появятся, когда смену проведёт приложение.

## 6. Мобильное приложение на эмуляторе

### 6.1. Открыть проект

1. Запустите Android Studio → **Open** → выберите папку `aramsamsam/android` (именно `android`, а не корень репозитория).
2. Студия начнёт **Gradle Sync**: прогресс виден внизу справа. Первый раз это 5–10 минут, потому что скачивается Gradle 8.9 и библиотеки.
3. Если студия предложит обновить Android Gradle Plugin, нажмите **«Don't remind me»** / не обновляйте: проект настроен на AGP 8.5.2.
4. Если появится «SDK location not found» или «Android SDK Platform 34 not installed», нажмите ссылку **Install** в сообщении. Либо вручную: Settings → Languages & Frameworks → Android SDK → вкладка SDK Platforms → поставьте галочку **Android 14 (API 34)** → Apply.

### 6.2. Создать эмулятор

1. **Device Manager** (иконка телефона справа) → **+** → **Create Virtual Device**.
2. Модель: **Pixel 6** (или любая с Play Store — значок магазина в колонке).
3. Образ системы: **API 34 (Android 14)** с Google Play. Для Mac на M1/M2/M3 выберите образ **arm64-v8a**. Нажмите Download рядом с ним.
4. Finish.

> Google Play в образе нужен: геолокация в приложении работает через Google Play Services.

### 6.3. Запустить

1. Сверху выберите конфигурацию **app** и созданный эмулятор.
2. Нажмите зелёный ▶ **Run**. Эмулятор загрузится, приложение установится и откроется.

### 6.4. «Перенести» эмулятор на базу

Начать смену можно только на территории базы, поэтому эмулятору нужно задать координаты.

1. На панели рядом с эмулятором нажмите **⋯ (Extended controls)** → **Location**.
2. Вверху выберите **Single points**, в поиске введите координаты демо-базы: `54.1063, 44.9395` → **Set location**.
   Эти координаты можно поменять: свои базы задаются в веб-панели на вкладке «Базы».
3. Откройте на эмуляторе Google Maps и убедитесь, что точка стоит там, где нужно. Это заодно «будит» геолокацию.

### 6.5. Вход и проверка сценария

1. На экране входа поле **«Адрес сервера»** уже заполнено значением `http://10.0.2.2:3000`. `10.0.2.2` — это ваш компьютер, если смотреть из эмулятора. Менять ничего не нужно.
2. Логин `ivanov`, пароль `1111` → **Войти**.
3. Разрешите доступ к геолокации, камере и уведомлениям.
4. **Начать смену** → карточка должна стать зелёной: «Вы на базе „Машинный двор“».
5. Выберите технику (например, МТЗ-1221), введите моточасы и топливо и **сфотографируйте** оба показания. Камера эмулятора показывает виртуальную комнату, для проверки этого достаточно. → **Начать смену**.
6. В веб-панели на вкладке **Смены** появится смена со статусом «Идёт». Если её нет, проверьте строку в шапке приложения: там должно быть «Всё отправлено».
7. **Заправка** → введите литры → **Сохранить**.
8. **Закрыть смену** → показания в конце и два фото → **Закрыть смену**. В веб-панели смена перейдёт в статус «Ждёт проверки», и фото откроются по клику.

**Проверка офлайн-режима:** в эмуляторе включите режим полёта, проведите целую смену, затем выключите режим полёта. Через несколько секунд всё уйдёт на сервер, а счётчик «Ждут отправки» обнулится.

**Проверка антифрода:** в Extended controls → Location поставьте точку в нескольких километрах от базы, например `54.14, 44.94`. Кнопка «Начать смену» станет недоступна, а приложение покажет, сколько осталось до базы.

## 7. Мобильное приложение на настоящем телефоне

### 7.1. Узнать IP компьютера

Телефон и компьютер должны быть в **одной Wi-Fi сети**.

```bash
# macOS
ipconfig getifaddr en0
# Windows (PowerShell): ищите «IPv4-адрес» у Wi-Fi адаптера
ipconfig
```

Получится адрес вида `192.168.1.57`.

Проверьте с телефона: откройте в браузере телефона `http://192.168.1.57:3000/api/health`. Должен прийти ответ `{"ok":true...}`.
Если страница не открывается:
- **macOS:** Системные настройки → Сеть → Файрвол. Разрешите входящие подключения для Docker (или временно выключите файрвол).
- **Windows:** при первом запуске Docker разрешите доступ в «Частных сетях». Проверьте, что сеть Wi-Fi отмечена как «Частная».
- Гостевые и корпоративные Wi-Fi часто изолируют устройства друг от друга. В таком случае раздайте интернет с телефона на ноутбук или используйте домашний роутер.

### 7.2. Установить приложение

1. На телефоне включите **режим разработчика**: Настройки → О телефоне → 7 раз нажмите на «Номер сборки».
2. Настройки → Для разработчиков → включите **Отладку по USB**.
3. Подключите телефон кабелем и подтвердите на телефоне «Разрешить отладку».
4. В Android Studio выберите телефон в списке устройств → ▶ **Run**.

### 7.3. Войти

На экране входа в поле **«Адрес сервера»** укажите `http://192.168.1.57:3000` (ваш IP из 7.1). Логин `ivanov` / `1111`.

### 7.4. Создать базу там, где вы находитесь

Демо-база находится в Мордовии, поэтому для проверки «на месте»:
1. Веб-панель → **Базы** → **Добавить базу** → кликните по карте на своём доме или университете → радиус 200–300 м → **Сохранить**.
2. В приложении: **Меню → Отправить сейчас**. Приложение загрузит новую базу, после чего можно начинать смену.

### 7.5. APK-файл для раздачи (без кабеля)

Android Studio → **Build → Build App Bundle(s) / APK(s) → Build APK(s)**. Готовый файл лежит в
`android/app/build/outputs/apk/debug/app-debug.apk`. Его можно отправить в Telegram и установить на любой Android 8+ (телефон попросит разрешить установку из неизвестных источников).

## 8. Проверка без телефона и без датчиков: симулятор

Один раз в корне проекта установите зависимости:

```bash
npm install
```

### Симулятор водителя

Притворяется мобильным приложением: проводит смену за последние 10 часов и отправляет её через тот же API. Пакет отправляется **дважды**, чтобы проверить, что дублей нет.

```bash
npx tsx simulator/sim.ts driver --login ivanov --password 1111 --scenario normal
npx tsx simulator/sim.ts driver --login petrov --password 2222 --scenario overuse        # перерасход
npx tsx simulator/sim.ts driver --login sidorov --password 3333 --scenario hours-padding # приписка моточасов
npx tsx simulator/sim.ts driver --login ivanov --password 1111 --scenario outside       # старт в 3 км от базы
```

После каждой команды в веб-панели на вкладке «Нарушения» появятся новые записи.

### Симулятор трекера (этап 2, датчики)

Притворяется GPS-трекером с CAN или ДУТ и отправляет сутки телеметрии по настоящему протоколу. Трекер с IMEI `356307042441013` уже привязан к «Кировцу» в демо-данных.

```bash
# Teltonika, ночной слив 60 л
npx tsx simulator/sim.ts tracker --protocol teltonika --imei 356307042441013 --scenario drain
# обычный день, ложных сливов быть не должно
npx tsx simulator/sim.ts tracker --protocol teltonika --imei 356307042441013 --scenario normal
# заправка, не внесённая в систему
npx tsx simulator/sim.ts tracker --protocol teltonika --imei 356307042441013 --scenario refuel
# движение ночью без открытой смены
npx tsx simulator/sim.ts tracker --protocol teltonika --imei 356307042441013 --scenario night-move
```

Затем откройте веб-панель → **Техника → Кировец** → **Проверить на сливы**. Сервер и сам проверяет телеметрию раз в 5 минут.

Для протокола **Wialon IPS** заведите в веб-панели новую технику: IMEI `861230043907626`, протокол «Wialon IPS», шаблон расшифровки «Galileosky / Arnavi по Wialon IPS». Затем выполните:

```bash
npx tsx simulator/sim.ts tracker --protocol wialon --imei 861230043907626 --scenario drain
```

Как подключить настоящие датчики и где их взять, описано в [docs/HARDWARE.md](HARDWARE.md).

## 9. Режим разработки

Для разработчиков: изменения в коде подхватываются сразу, без пересборки Docker.

### 9.1. В Docker оставить только базу и хранилище

```bash
docker compose stop backend web     # если стенд был запущен целиком
docker compose up -d db
```

### 9.2. Backend

```bash
cd backend
cp .env.example .env        # настройки по умолчанию подходят для локального запуска
npm install
npm run start:dev           # сервер на http://localhost:3000, перезапускается при сохранении файла
```

В другом окне терминала:

```bash
cd backend
npm run seed                # демо-данные (если база пустая)
```

Фото в режиме разработки сохраняются в папку `backend/uploads` (`STORAGE_DRIVER=disk` в `.env`).

### 9.3. Веб-панель

```bash
cd web
npm install
npm run dev                 # http://localhost:5173
```

Запросы на `/api` автоматически проксируются на `localhost:3000`.

### 9.4. Android

Без изменений, см. раздел 6. Backend по-прежнему на порту 3000, поэтому адрес `http://10.0.2.2:3000` подходит.

## 11. Полезные команды

| Задача | Команда |
|---|---|
| Остановить всё | `docker compose stop` |
| Запустить снова | `docker compose up -d` |
| Пересобрать после `git pull` | `docker compose up -d --build` |
| Логи backend | `docker compose logs -f backend` |
| Логи всех сервисов | `docker compose logs -f` |
| Перезапустить только backend | `docker compose restart backend` |
| Консоль базы данных | `docker compose exec db psql -U agro agro` |
| **Полностью очистить базу и фото** (удалит все данные!) | `docker compose down -v`, затем `docker compose up -d --build` и снова seed |
| Обновить код из GitHub | `git pull`, затем пересборка |

Пример запросов в консоли базы:

```sql
SELECT name, last_fuel_l, last_seen_at FROM vehicles;
SELECT type, severity, message FROM anomalies ORDER BY created_at DESC LIMIT 10;
\q
```

## 12. Настройки

### Секреты и пароли

В `docker-compose.yml` уже есть значения для локального запуска. Для своих значений создайте в корне проекта файл `.env` (он не попадает в git):

```env
JWT_ACCESS_SECRET=длинная-случайная-строка-1
JWT_REFRESH_SECRET=длинная-случайная-строка-2
TELEMETRY_HTTP_KEY=ключ-для-своих-устройств
TELEGRAM_BOT_TOKEN=
```

После изменения: `docker compose up -d`.

Случайную строку можно сгенерировать командой `openssl rand -hex 32`.

### Уведомления в Telegram

1. В Telegram напишите **@BotFather** → `/newbot` → получите токен вида `123456:ABC...`.
2. Впишите токен в `.env`: `TELEGRAM_BOT_TOKEN=123456:ABC...` → `docker compose up -d`.
3. Создайте группу диспетчеров и добавьте туда бота.
4. Узнайте id группы. Самый простой способ — добавьте в группу **@getmyid_bot**, он пришлёт id вида `-1001234567890`.
5. Веб-панель → **Настройки** → «ID чата» → **Сохранить настройки**.

Нарушения средней и высокой важности начнут приходить в группу.

### Порты

| Порт | Сервис | Если занят |
|---|---|---|
| 8080 | веб-панель | в `docker-compose.yml` у `web` замените `"8080:80"` на `"8081:80"` |
| 3000 | API | `"3001:3000"` у backend; адрес в приложении тогда `:3001` |
| 5432 | PostgreSQL | частая ситуация, если у вас уже стоит свой Postgres: замените на `"5433:5432"` |
| 5027 / 20332 | шлюзы трекеров | обычно свободны |

## 13. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop не запущен. Откройте его и дождитесь «Engine running». |
| `no matching manifest for linux/arm64` у `db` | Старая версия `docker-compose.yml`. Выполните `git pull`: у сервиса `db` должна быть строка `platform: linux/amd64`. Включите Rosetta (раздел 2). |
| `pull access denied for minio/minio` | У вас старая версия проекта: MinIO удалили из Docker Hub. Выполните `git pull`, в новом `docker-compose.yml` MinIO нет. |
| Docker не может скачать образ (`TLS handshake timeout`, `403`, `failed to resolve reference`) | Проблемы доступа к Docker Hub. Docker Desktop → Settings → Docker Engine → добавьте `"registry-mirrors": ["https://mirror.gcr.io"]` → Apply & restart. Либо попробуйте через другую сеть или VPN. |
| `port is already allocated` | Порт занят другой программой, см. таблицу портов в разделе 12. |
| Сборка backend упала с ошибкой TypeScript (`error TS…`) | Пришлите текст ошибки — поправлю. Проект писался без возможности полной сборки, мелкие ошибки компиляции возможны. |
| Backend в логах пишет `password authentication failed` / `ECONNREFUSED db` | База ещё стартует: подождите 10–20 с, затем `docker compose restart backend`. Если менялись пароли — `docker compose down -v` (сотрёт данные). |
| `extension "postgis" is not available` | Используется обычный Postgres вместо PostGIS. В режиме разработки поднимайте базу из compose (`docker compose up -d db`). |
| Веб-панель открывается, но после входа «Ошибка 502» | Backend не запустился. Смотрите `docker compose logs backend`. |
| В карточке смены фото не открываются | Фото ещё не загрузилось с телефона (написано «ждёт»): в приложении нажмите «Меню → Отправить сейчас». Проверьте, что файлы есть: `docker compose exec backend ls -R /data/photos`. |
| Android Studio: `Unsupported Java` / `requires Java 17` | Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK → выберите **jbr-17** (встроенный). |
| Android Studio: ошибка Gradle при синхронизации | File → Invalidate Caches → Invalidate and Restart. Проверьте интернет: нужен доступ к `dl.google.com` и `repo.maven.apache.org`. Если ошибка в нашем коде — пришлите её текст. |
| Приложение: «Нет связи с сервером» | Эмулятор: адрес `http://10.0.2.2:3000`. Телефон: `http://<IP компьютера>:3000`, одна Wi-Fi сеть, проверка `…/api/health` в браузере телефона (раздел 7.1). |
| Приложение: «Вы не на базе», хотя вы на месте | Создайте базу в своём месте (раздел 7.4) и нажмите «Меню → Отправить сейчас», чтобы приложение загрузило её. |
| Приложение: «Слабый сигнал GPS» | В помещении GPS неточный. Выйдите на улицу или увеличьте «Точность GPS для старта» в веб-панели → Настройки. |
| Приложение: «Определяем местоположение…» висит в эмуляторе | Задайте точку в Extended controls → Location и откройте Google Maps в эмуляторе, чтобы «разбудить» геолокацию. |
| Симулятор: `Сервер не принял IMEI` | IMEI не привязан к технике. Веб-панель → Техника → Изменить → «IMEI трекера». |
| Симулятор: `ECONNREFUSED 127.0.0.1:5027` | Backend не запущен, либо порт закрыт. Проверьте `docker compose ps`. |
| `npx tsx` долго думает | При первом запуске он скачивается. Сначала выполните `npm install` в корне проекта. |

Если проблема не из таблицы, пришлите:
1. вывод `docker compose ps`;
2. последние 50 строк логов: `docker compose logs --tail 50 backend`;
3. что вы делали и что ожидали увидеть.

## 14. Запуск на сервере для пилота

Чтобы водители хозяйства работали с настоящих телефонов через мобильный интернет, нужен сервер с публичным адресом.

1. **VPS** с Ubuntu 22.04/24.04, 2 ядра, 4 ГБ RAM, 40 ГБ диска. Подойдут Timeweb Cloud, Selectel, Yandex Cloud, VK Cloud.
2. Установите Docker: `curl -fsSL https://get.docker.com | sh`.
3. `git clone …` → создайте `.env` с **новыми** секретами (раздел 12) → `docker compose up -d --build`.
4. **Домен и HTTPS.** Направьте домен на IP сервера и поставьте перед `web` обратный прокси с сертификатом Let's Encrypt (например, Caddy: две строки конфигурации). После перехода на HTTPS уберите разрешение HTTP из `android/app/src/main/res/xml/network_security_config.xml`.
5. В файрволе откройте порты **80, 443** (веб и API), а для трекеров **5027** и **20332**. Порт 5432 наружу **не открывайте**: в `docker-compose.yml` для сервера уберите у `db` строку `ports`.
6. Фото по умолчанию лежат в томе `photos` на сервере. Включите их в резервные копии или переключитесь на S3-хранилище: в `.env` задайте `STORAGE_DRIVER=s3` и параметры `S3_*` (пример для Yandex Object Storage есть в `backend/.env.example`).
7. Сразу смените пароли демо-пользователей или не запускайте seed на боевом сервере. Хозяйство создаётся через суперадмина: веб-панель → «Хозяйства» → «Подключить хозяйство».
8. Резервные копии базы, раз в сутки по cron:
   `docker compose exec -T db pg_dump -U agro agro | gzip > backup_$(date +%F).sql.gz`
